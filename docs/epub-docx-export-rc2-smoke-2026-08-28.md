# EPUB/DOCX accepted-revision export proof — 2026-08-28

## Scope

This increment extends the existing `publish_novel_manuscript` Tool inside the
single `@novel-agent/novel-project` plugin. An optional `format` selects `epub`
or `docx`; omitting it retains the existing UTF-8 publication path. The Tool can
select one manuscript unit from an explicit accepted aggregate revision or,
with `scope: book`, assemble the accepted Chapter manuscripts below one accepted
Book narrative unit. Both paths use stock DSH approval, write only after
approval and never advance Canon.

The call presenter now declares the existing DSH mutation vocabulary
`kind: edit` plus the destination `locations` entry. That makes a successful
publication eligible for the stock Produced Files row without adding any
novel-agent UI.

No export Tool, download manager, Better Sidebar tab/viewer, Pi TUI extension,
adapter, Profile, Bundle, Workbench or document settings screen was added.
Generic upload and document extraction remain in separately installed
`dsh-file-upload@0.4.3`.

## Observed Host integration

Each case boots the real DSH Tool Runtime, storage, Workspace, generated Remote,
approval pipeline and `novel-project` service in process. The filesystem seam is
a focused test provider whose `processPath()` returns a real temporary path;
the final bytes are written and read through the operating-system filesystem.

The fixture accepts `chapter-a` as R1, then another unit as R2. It asks aggregate
R2 to publish `chapter-a`, proving that selection returns
`sourceRevision: 1` rather than pretending the unit was rewritten at R2.

For both EPUB and DOCX:

1. the target is absent while the stock approval request is pending;
2. only `allowed-once` releases the write;
3. the receipt reports aggregate R2, source R1, unit id, title, format,
   `create`, character count and the exact byte count read from disk;
4. the output starts with the ZIP local-file signature, not UTF-8 or Base64
   stand-in text;
5. `writeText` is never called;
6. `resolve(destination, { cwd: policy.workspaceRoot, signal })`, `stat(target)`,
   `processPath(target)` and the DSH policy lookup are explicitly asserted;
7. both accepted manuscript projections remain intact and the current head
   remains R2 after publication.

The EPUB proof additionally checks that the first ZIP entry is the uncompressed
`mimetype` with value `application/epub+zip`, then opens and checks
`META-INF/container.xml`, `OEBPS/content.opf`, navigation and chapter XHTML for
the exact Chinese title and text. The DOCX proof opens the ZIP, checks
`[Content_Types].xml` and `word/document.xml`, and finds the exact title and both
Chinese manuscript lines.

## Whole-book hierarchy proof

The whole-book fixture intentionally accepts Chapter B first as R1 and Chapter A
second as R2, while its accepted narrative projection orders A before B under
`book-main → volume-1 → arc-1`. Publishing `book-main` at aggregate R2 therefore
proves that assembly follows accepted Canon hierarchy rather than acceptance
time, source revision or lexical manuscript-map order.

For both EPUB and DOCX:

1. stock approval is requested once and the destination is absent until
   `allowed-once`;
2. the receipt reports ordered `unitIds: [chapter-a, chapter-b]` and per-unit
   source revisions `[R2, R1]`;
3. EPUB OPF/spine, navigation and numbered chapter XHTML place A before B;
4. DOCX `word/document.xml` places the book title, Chapter A title/body and
   Chapter B title/body in that order;
5. the accepted head remains R2.

The one-unit path keeps its original request and EPUB `text/chapter.xhtml`
shape, so this feature adds no migration or second publication contract.

## Binary target seam

DSH `0.1.1-rc.2` exposes `resolve`, `stat`, `processPath`, `readBytes` and
text-only `writeText`; it does not publish `writeBytes`. The implementation uses
the public `processPath(target)` handoff after stock Publish approval and DSH
target resolution, then calls Node `writeFile()` with the generated bytes.

This preserves DSH approval, canonical target identity and the display-path
receipt. It does not traverse the text-only `dsh-fs-sandbox` mutation fence, so
this evidence does not claim binary filesystem sandbox enforcement.

## Adopted libraries

- `docx@9.7.1` (MIT) produces the DOCX Buffer with `Document`, `Paragraph` and
  `Packer.toBuffer()`.
- `fflate@0.8.3` (MIT, zero dependencies) creates the minimal EPUB 3 ZIP and is
  also used by the test to re-open both formats.

Both remain Host-only implementation dependencies. The client build continued
to report only `zod` as bundled. Exact artifacts, lifecycle scripts, closure
licenses, rejected candidates and the rc.2 seam are documented in

## Claim boundary

This verifies one accepted manuscript unit or one whole Book per real EPUB 3 or
DOCX binary at the Host integration scope, including approval gating, stock
Produced Files intent, accepted hierarchy ordering, per-unit historical source
revision and unchanged Canon. It does not verify covers, embedded media,
templates, original source bytes/BOM, a binary-specific visible stock-Agent/Profile
run, production installation or user acceptance.
