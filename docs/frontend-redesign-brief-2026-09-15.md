# 任务：为「小说协作写作工作台」做全量高保真交互原型

你是一名同时懂信息架构、文学类产品与视觉设计的设计师。请为一个「写作者与 AI 协作写长篇网文」的桌面工作台，产出一份**单页 HTML 可点击交互原型**（全部界面 + 全部状态，全量实现，不允许占位符）。

## 1. 用户与目标

- **用户**：中文长篇网文作者。每天做的事：和 AI 讨论故事、让 AI 写下一章、审阅 AI 的提案、读改已接受的正文、盯伏笔和人物状态。
- **产品定位**：作者是决策者，AI 是稿手。所有「故事事实」只有作者接受后才会生效（提案 → 审阅 → 接受/拒绝 → 新版本）。界面要让作者**专注于和 AI 协作写作**，而不是操作工程工具。
- **设计目标**：
  1. 写作者全程看不到工程术语与裸 JSON；
  2. 打开工作台的第一屏是**故事地图**——一眼看清人物、关系与故事进展；
  3. 从「看」到「写」到「审」到「读」的每一步都在 3 次点击内；
  4. 界面像编辑部的书房：纸墨、安静、耐读，适合每天长时间面对。

## 2. 产出物要求

- **一个 HTML 文件**（内嵌 CSS/JS，可离线双击打开），用页面顶部一条细长的「原型屏幕切换条」在全部屏幕间跳转；同时原型内部的真实交互（点节点、开抽屉、审提案）必须可点击走通。
- **必须模拟整个宿主窗口**：左侧极窄的会话栏 + 右侧主区；主区顶部有「Chat / 写作台」两个页签（写作台是本设计的重点，Chat 页签用于展示内联提案卡与写作条）。宿主外壳请用中性灰极简处理，**不要重设计宿主**，它只是背景。
- 画布基准 **1440 × 900**，最低 **1280** 宽可用；不做移动端。
- **全量实现**：所有屏幕完整、所有按钮有 hover / active / disabled / 加载四态、所有文案为简体中文、无 lorem、无 TODO、无死按钮。
- 不引用任何外部资源（图片/CDN 字体/图标库）；图标用内联 SVG 或字符；字体只用系统字体栈。
- 交付时另附一份「设计 token 表」（CSS 变量：日/夜两套颜色 + 字阶 + 间距 + 圆角）与「组件清单」。

## 3. 视觉系统

**方向：纸墨书房。** 暖纸底、墨色文字、一个克制的强调色；界面安静，正文耐读。

- 强调色 **朱砂红**（用于接受、待审、批注、关键动作）；`warning` 另用暖黄，不得与强调色混淆。语义色：成功=低饱和墨绿，错误=暗红，信息=灰蓝；三者只用于状态点与提示条，不铺面。
- **日/夜双主题**，写作台头部一个日/夜切换；夜间是深暖灰（不是纯黑），文字变暖白。
- 颜色以语义角色命名（纸、纸-2、墨、墨-2、墨-3、线、朱砂、朱砂-淡、暖黄、墨绿、暗红、阴影），不要出现品牌深色大色块；header 不再用深藏青。
- 字体：正文与标题用宋体类衬线（`"Source Han Serif SC","Noto Serif SC","Songti SC",SimSun,serif`），界面控件用无衬线（`"PingFang SC","Microsoft YaHei",system-ui,sans-serif`），等宽只在诊断模式使用。
- **中文阅读规范**：正文 16–18px、行高 ≥1.8、行宽 ≤ 约 40 字、段距 0.8–1em、两端不强制对齐；阅读区背景比界面底更暖一点。
- 管理类界面 13–14px，信息密度中等；留白充足，卡片圆角 8–10px，边框 1px 细线，阴影极轻。

## 4. 信息架构

写作台 = **地图 + 左侧分组导航 + 右侧上下文栏**。

### 4.1 故事地图（默认第一屏，关系图谱为主）

- **节点**：人物。半径或描边反映戏份/当前章出场；颜色反映所属势力（4 个势力 + 无势力）；节点上有状态点（情绪/未收束欠债）。
- **边**：人物关系。**同一条边必须表达双向语义**（例如上下两半或双线描边）：A→B 的信任/冲突/承诺与 B→A 各自独立；边 hover 显示一句话摘要；选中节点时边加亮，其余淡出。
- **规模能力（40–120 人）**：按势力分簇、按地点分布、搜索定位（输入人名自动聚焦并高亮邻居）、按卷/弧过滤「本卷出场」、手动拖拽固定位置（双击解除）、缩放/平移、图例。
- **不允许毛线团**：默认视图只呈现「主要人物 + 与其相关的主线关系」，次要人物折叠成势力簇的「+N」气泡，点击展开。

### 4.2 左侧分组导航（分组，不是页签）

- 分组一「本章」：当前章卡片（卷/章号/标题/字数进度/状态）、本章合同（作者语言的任务清单：视角、故事时间、必须出现、禁止矛盾、长度范围、接受标准）。
- 分组二「故事状态」：伏笔与线索板、未收束债务、人物弧线与情绪、关系史、时间线。
- 分组三「记忆与设定」：写作记忆（AI 记得什么、来源与新鲜度）、世界观与连续性。
- 分组四「推演」：读者体验模拟、沙盒推演（MiroFish）。
- 分组五（默认隐藏，见 4.7）：诊断。
- 点击分组项 → 右侧滑出抽屉（轻量视图）或进入全幅页（伏笔板、时间线、模拟这类宽内容）。

### 4.3 右侧上下文栏（常驻）

- 当前章卡片：`卷二 · 第 6 章《冷库之下的通道》 · 待审`，字数目标进度条。
- 待审提案入口（有提案时高亮，带「待审」徽标）：点击进入提案审阅全幅。
- 主按钮「继续写下一章」；次按钮「审阅本章」。
- 版本号 `R5` + 历史入口（历史版本是地图的一个可开层：版本列表、对比摘要、回滚确认；回滚后顶部版本号变化）。

### 4.4 人物档案抽屉

点人物节点从右侧滑出：头像位（无图时用姓名首字印章式圆形）、身份/一句话简介、当前状态、情绪、人物弧线（从→到 的简短描述）、**关系列表**（每行：对方姓名 + 两个方向各一句当前状态 + 信任/冲突强度），**出场章节列表**（卷章 + 该章里他做了什么，点击进入正文阅读），底部一个朱砂色动作「让 AI 从这个人物继续写」。

### 4.5 提案审阅（全幅）

- 顶部：版本变化 `R5 → R6`、章号与标题、约 2,800 字、`6 条设定变更 · 3 个审阅问题`。
- 正文预览区：可滚动阅读本章草稿（正文片段见附录 A）。
- **设定变更列表**：每条一句话写作语言描述（如「陈默得知 3 号冷库存在地下通道」），右侧「接受 / 拒绝」二选一（默认接受），拒绝时可留一句理由。**不出现 JSON、delta、kind 等词。**
- **审阅问题**：严重度标签（高/中/低）+ 问题 + 建议 + 出处锚点（显示为「第 4 章 · 陈默受伤」这样的可点击引用）。
- 底部：影响预览（`R5 → R6：正文 1 篇 · 设定变更 6 条 · 审阅问题 3 个`，以人类语言摘要，不显示原始 impact 结构）、朱砂主按钮「接受本章」、次按钮「暂不处理」。
- 点击「接受本章」→ 先出现影响预览弹层 → 确认后版本号变 `R6`，地图上相关人物节点的状态点/边随之更新（如陈默与白桦的边加亮变化），并出现一条轻提示「已接受为 R6」。

### 4.6 对话内联（Chat 页签视角）

- **回合尾部提案决策卡**：AI 回合结束后出现的完整决策卡——章号/标题/字数/`6 条设定变更 · 3 个审阅问题` + 按钮：`接受本章`、`预览影响`、`在写作台打开`、`丢弃`。点击「在写作台打开」切到写作台页签并打开对应提案。
- **工具调用详情**：AI 调用「生成提案」工具时，展开详情显示结构化摘要（章节卡 + 变更条数），不是裸 JSON；JSON 只在诊断模式可见。
- **写作条**（输入框上方常驻）：`卷二 · 第 6 章 待审` + 字数进度 + `继续写第 7 章` / `审阅本章` / 版本 `R5`；点击「继续写第 7 章」时在输入框预填一条中文指令草稿（如「按本章合同写第 7 章，视角：陈默，注意第 4 章他左臂有伤未愈」），由作者决定发送。
- 会话头部工具：项目名 + 版本 `R5` + 「打开写作台」。

### 4.7 诊断模式（默认隐藏）

设置里的「开发者诊断」开关（默认关）。开启后左侧导航出现「诊断」分组：原始账本（控制包、生命周期、逐字段视图、模拟器的原始输出）以朴素但整洁的等宽表格呈现；只求可用、不参与主视觉。关闭后整个分组消失。

### 4.8 沙盒推演（MiroFish）入口

左侧「推演」分组 → 全幅页：实验列表（读者反应 / 人物压力）、新建实验表单（选择固定版本、人物子集、问题）、实验详情（人物反应、信息扩散、误读、联盟、未解决钩子）。**未连接状态**必须设计：一张说明卡「沙盒侧车未连接」+ 连接指引按钮，实验功能置灰。

## 5. 边界状态（必须实现）

1. **空项目**：没有任何 Canon 事实时，地图区域是一张「立项」引导卡：三行说明 + 朱砂按钮「让 AI 生成立项提案」。
2. **加载中**：地图与侧栏用骨架屏；按钮进入加载态（文案如「正在计算影响…」）。
3. **缺插件**：某一视图依赖的领域插件未安装时，显示可读错误卡（如「未安装小说规划插件，本章合同暂不可用」+ 重试），页面其余部分正常。
4. **窄窗 1280**：左导航折叠为图标 + tooltip，右侧栏可收起，地图自适应，不出现横向滚动。
5. **提案被拒绝/过期**：提案卡显示「基于 R5，当前已是 R6，此提案已过期」+ 丢弃按钮。

## 6. 交互与可访问性硬性要求

- 关键链路 ≤3 击：`地图 → 人物 → 出场章节 → 正文`；`Chat → 内联卡 → 接受`；`写作台 → 待审提案 → 接受本章`。
- 键盘：Tab 顺序合理、Esc 关闭抽屉/弹层、Enter 确认主按钮、抽屉打开时焦点进入并困住。
- 对比度达 WCAG AA（正文 4.5:1）；焦点环用朱砂描边，清晰可见。
- 数字（字数、版本、条数）用等宽数字对齐；日期用「第 41 天」这类故事内表述与真实时间并存时，以故事内表述优先（悬疑作品，故事内时间由数据给出）。

## 7. 数据与文案

- 统一使用附录 A 的《雾港夜航：第七码头》样例数据（18 人物、4 势力、5 地点、3 物件、6 伏笔/线索、3 卷 12 章、1 份待审提案、写作记忆、时间线、3 条未收束债务）。**不要自造与附录 A 矛盾的人物名、势力名或章节标题。**
- 界面文案为简体中文，语气克制、书面；按钮用动词（接受本章 / 丢弃 / 继续写第 7 章），避免「提交」「执行」这类工程词。
- 术语统一：提案（不是 packet）、设定变更（不是 delta）、审阅问题（不是 issue）、版本 R5（不是 revision 5）、伏笔/线索/谜团、未收束债务、写作记忆、沙盒推演。

## 8. 验收（交付前逐条自检）

- [ ] 全部屏幕与状态齐全，无占位符、无死按钮、无英文残留；每个交互元素四态完整。
- [ ] 界面上不出现 JSON / delta / Canon / kind / 账本 / 控制包 等工程词（诊断模式除外）。
- [ ] 地图在 40+ 人物时有分簇、搜索、过滤、钉位；双向边语义一眼可读。
- [ ] 中文正文阅读舒适（16–18px、行高 ≥1.8、行宽 ≤40 字）。
- [ ] 1280 宽无横向滚动；键盘可达；对比度 AA；日夜两套 token 均可切换。
- [ ] 三条关键链路各 ≤3 击可走通；接受提案后版本号与地图状态同步变化。
- [ ] 空项目 / 加载 / 缺插件 / 窄窗 / 过期提案 五个边界态均有设计。
