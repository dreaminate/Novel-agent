# 中长篇网文创作与小说 Agent 产品研究

**研究截止日：** 2026-09-05  
**范围：** 中国大陆中文网文创作；纵向窗口 2018-01-01 至 2026-09-05；补充英文 AI 创作研究。  
**目的：** 为 DSH 小说 Agent 定义真实创作流程、验收小说、插件边界和开工前实施计划。

## 研究方法与证据边界

本轮先运行了离线横纵研究计划，再使用只读公开网页直连。百度、Google 和部分学术站点存在验证码或 Cloudflare，因此没有把搜索摘要当作事实；可引用内容来自阅文作家专区原文、arXiv 摘要、Crossref 元数据和 Novelcrafter 官方功能页。作者课程属于平台编辑/作者经验，能证明“平台如何教作者写”，不能证明所有作者都遵循同一方法。AI 论文证明实验观察和能力边界，不能直接外推中文网文商业结果。

## 网文真实创作流程

阅文作家专区的“网文全武行第一期”把开书拆为六步：确定题材、确定写法、确定主角身份与处境、先写前六万字综述再做细纲、写一两万字寻求编辑意见、最后发布。内容强调先从读者情感需求和题材库出发，再落到主角的职业/生活压力，而不是打开文档后边写边想。

从该流程和同专区其他课程可以还原出一个可执行的中长篇流水线：

1. **选题与读者契约**：题材、细分赛道、读者幻想、情绪基调、差异化卖点、禁区。
2. **一句话 premise 与简介**：主角是谁、当前处境、核心冲突、持续追读理由。
3. **主角和世界底盘**：主角生活状态、职业、资源、缺陷；世界规则、势力、地点和知识边界。
4. **长线大纲**：全书目标、卷/篇章阶段、主要反派或障碍、终局方向、未偿还债务。
5. **中线综述**：先规划前 3–6 万字，确保开篇动作、首个小高潮和第一阶段闭环。
6. **章纲/场景卡**：每章目标、视角、时间地点、动作—反应、信息揭示、承诺推进、章末钩子。
7. **逐章生产**：Plan → Draft → 自检 → Review → 作者接受；下一章只读取已接受状态。
8. **连载反馈**：根据读者评论、追读、收藏、弃读位置和编辑意见调整后续规划，但不追逐单一指标破坏主线。
9. **阶段复盘**：卷末回收伏笔、更新人物/关系/世界状态、重排剩余路线并准备下一卷。
10. **完结与再利用**：保留可追溯版本，导出正文、简介、设定、投稿材料和版权改编所需资料。

平台课程还反复强调开头的重要性：前三章要让读者知道类型、主角和基本冲突，避免人物过多、设定堆砌和与主角无关的长篇背景；“黄金三章”不是固定数字，而是尽快建立读者继续阅读的理由。

## 创作难点与痛点

### 1. 开书容易，稳定连载难

阅文课程将“不卡文让剧情丰满”“追订稳定不崩的大长篇”单独作为主题，说明真正的难点在持续交付。作者需要同时维护当天章节、下一阶段章纲和全书主线，任何一层断裂都会出现水字数、重复冲突或突然换地图。

### 2. 期待感不是单纯堆高潮

编辑课程把最小剧情单元概括为“动作—反应”：主角或环境发生改变，相关人物和局势必须反馈；只有动作没有反应会像日记，只有震惊没有主角收益也没有爽点。冲突要围绕主角主线，从生活/职业处境出发，通过意外和信息差制造期待。

### 3. 长线伏笔很容易失效

平台编辑指出，伏笔跨距过长会被读者遗忘，单纯标记“这里是伏笔”不能保证回收；长篇需要多条主线和阶段性总结把事件重新连成整体。工具必须记录伏笔的首次证据、当前承诺、允许的回收窗口和实际回收结果。

### 4. 人物和世界设定会在连载中漂移

人物不能只是一张静态卡片：职业、资源、目标、信念、关系和代价会随事件变化。世界规则也会因新地图、新势力和新能力不断暴露。没有 revision-bound 状态，模型会把草稿、废案和已接受事实混在一起。

### 5. 读者契约与商业节奏存在压力

平台内容强调题材定位、简介、前三章、读者期待和追订稳定。作者既要满足类型读者的爽点/情绪，又要保持人物可信、冲突有生活根基；“不符合读者预期”与“千篇一律”同时存在，不能用一个通用评分解决。

### 6. AI 的典型失败不是不会写，而是无法持续控制

LongWriter 研究发现，长上下文模型能读很多内容，却常在约 2,000 词附近停止长输出；AgentWrite 通过拆任务和阶段生成才把单次连贯输出扩展到 20,000 词以上。对网文的含义是：不能把整卷一次性塞给模型，必须采用章节/场景级计划、来源锚点、增量草稿和阶段性重读。

### 7. 过度依赖模型会产生同质化和锚定

一项关于创意协作方式的实验发现，把模型当“ghostwriter”对专家用户可能有害，作为“sounding board”提供反馈更有帮助；另一项预注册研究发现，大规模 GPT-4 写作会降低群体创意多样性。小说 Agent 应把模型定位为可审阅的策划、写手和编辑协作者，作者保持最终选择，不自动接受生成内容。

### 8. 现有工具偏“资料管理”，不等于创作控制

Novelcrafter 官方功能展示了行业常见表面：大纲/规划网格、场景状态、POV、手动引用、Codex 人物地点资料库、别名、提及时间线、聊天取材、按场景或整书选择上下文、审阅热力图和字数统计。这些功能证明作者需要结构化上下文和可见状态；它们没有自动保证因果、承诺兑现或跨章事实正确，这正是 DSH Canon/Revision/Review 的差异化空间。

### 9. MiroFish 适合做“群体反应”而不是直接充当剧情引擎

MiroFish README 明确支持把小说故事作为种子，流程是图谱构建、实体关系与 Agent 人设、OASIS 双平台多轮模拟、报告和 Agent 采访。代码审计显示其输入和状态围绕 Graphiti/Zep 图记忆、Twitter/Reddit profile、发帖/评论/转发/关注等社交动作；`SimulationRunner` 支持回合状态、暂停和采访，但没有小说地点移动、资源守恒、战斗前置条件、叙事因果账本或真正的 branch/replay API。MiroFish 根目录和后端均为 AGPL-3.0，OASIS 为独立 Apache 2.0 依赖。

因此 MiroFish 在小说产品中的第一价值是让多个“人物/读者 Persona”对章节、线索和干预做出可观察的群体反应；它的动作日志和报告可以成为 Review 的外部证据。剧情状态演化必须由小说适配层编译和解释，不能把 Twitter/Reddit 帖子直接当作 Canon 事实。若未来要做 A/B 剧情分支，需要在 MiroFish/OASIS 侧另立 AGPL fork，增加通用叙事动作、快照和分支接口。

## 产品结论

小说 Agent 的核心价值不是“生成更多字”，而是把作者的循环变成可回放的生产线：

```text
读者契约/题材
  → 长线路线图
  → 卷/阶段目标
  → 章纲与动作-反应卡
  → 草稿
  → 连续性/节奏/风格审阅
  → 作者逐项接受
  → 写作记忆与下一章上下文
  → 连载反馈进入下一轮规划
```

模型每次只获得当前任务需要的 revision-bound 上下文；任何新设定、正文、关系变化或伏笔回收都必须先成为 proposal，再由作者在同一 Result Packet 中接受。

## 验收小说：中长篇网文压力样本

### 书名与定位

**《雾港夜航：第七码头》**（原创测试样本）  
类型：现代都市异能 × 悬疑成长 × 职业群像；单主视角为主，少量带来源的读者/配角知识差。  
目标规模：4 卷、每卷 24 章、全书约 24–32 万汉字；首轮验收只实现前 12 章（约 3–4 万字）和一条可继续的卷级路线。

### 故事底盘

- 主角林砚是雾港夜班航标维护员，背负父亲失踪留下的债务，起点低、职业细节真实；
- 城市存在只能在潮汐低位显形的“旧港层”，但进入条件、代价和记忆影响必须遵守三条固定规则；
- 三个势力分别掌握航标、港务和旧港走私线，目标冲突但并非纯善恶；
- 核心谜团是父亲是否主动进入旧港，以及第七码头为何在官方地图上被删除；
- 主线承诺：主角解决债务并查清父亲下落；阶段承诺：修复航标、保护同事、识别内鬼；
- 关系线：林砚与搭档苏晚从互不信任到共同承担代价；反派顾沉拥有合理的制度性动机；
- 卷一结尾必须回答“第七码头存在”，同时留下“父亲曾主动删除一次航标记录”的新问题。

### 章节验收点

| 阶段 | 章节 | 必须观察到的行为 |
| --- | --- | --- |
| 开篇 | 1–3 | 第一章主角出现；职业冲突真实；一次打破平衡的动作；读者知道类型、主线和即时风险；每章有章末拉力 |
| 第一阶段 | 4–6 | 修复航标的小闭环；动作—反应成对；引入苏晚和一个可验证规则；首个小收益伴随代价 |
| 中段 | 7–9 | 旧港层第一次显形；至少两条线交叉；一枚伏笔有明确 source Anchor；人物选择改变关系和资源 |
| 阶段收束 | 10–12 | 第七码头线索被证实但不完全揭底；回收一枚短伏笔；保留一枚长伏笔；卷一剩余路线可由 accepted state 继续规划 |

### 验收指标

- **Canon 正确性**：所有已接受人物、规则、关系、时间和线索在 R1–R5 回放一致；废案不得进入下一章上下文。
- **章节结构**：12 章每章都有目标、障碍、动作—反应、信息变化和章末拉力；Review 能指出缺失项并给出证据锚点。
- **连续性**：故意制造三种错误（人物已知信息越界、规则违反、物件位置冲突），Checker 全部定位到章节/句段来源。
- **记忆边界**：请求 R2 时不得泄漏 R3 未接受内容；召回结果显示 revision、Anchor 和来源类型。
- **伏笔/承诺**：短线伏笔在 1–3 章内回收，中线伏笔在 10–12 章有进展；未回收项显示债务而不是自动判定失败。
- **作者控制**：拒绝正文但接受设定时，正文 projection 保持旧版；Apply/rollback 后 UI、Remote 和存储一致。
- **模型协作**：Plan、Draft、Review 可分别重试；任何一次模型失败都不污染 Canon，作者可以继续使用上一个 accepted Revision。
- **DSH 运行**：真实隔离 rc.2 Web Profile 完成安装、Tool/Remote/Skill、reload、跨 Session 读取和正常停止；不新增 Agent/Session/Store/Transport。

## 研究驱动的非目标

不把“写满几十万字”作为单次模型调用；不自动根据追读数据改写 Canon；不把 AI 生成的情绪评分当成市场预测；不把用户评论样本当作总体读者结论；不在首轮验收引入向量数据库、复杂多分支模拟或自动发布。
