# 任务：为「DSH 小说模式」设计整个 Web 前端的高保真交互原型

## 0. 背景（给你读，不要画进界面）

我们要给 DeepSeek Harness（DSH）做一个**专门的「小说模式」**：同一个 Host、同一套小说插件，
但**整个 Web 前端换成面向中文长篇网文作者的工作台**。这不是给现有界面加一个页签——左栏、
主画布、右栏、输入区、设置页、审批、进阶面板，**所有看得见的界面都由 novel-agent 自己拥有**；
DSH 只在看不见的地方提供会话装配、输入状态机、草稿/队列、审批、Jobs、Subagent、Skills 和传输。

三条硬约束：

1. **不要画 DSH 官方外壳，也不要画"宿主窗口模拟"。** 旧原型里那圈中性灰宿主框这次不需要——
   你画的就是产品本体，铺满整个窗口。
2. **视觉参考 Claude Code 桌面版**（本机 `/Applications/Claude.app`）的视觉语言与交互骨架：
   暖灰双主题、陶土色强调、克制的细线与圆角、密度适中、等宽只出现在诊断类界面。
   但**不要使用它的专有字体**（`anthropic-sans` / `anthropic-serif`），中文一律系统字体栈。
3. **工作目录里可以读到这些文件，请直接读，不要猜：**
   - `docs/frontend-redesign-brief-2026-09-15.md` — **附录 A 是本书的样例数据包，直接当作数据源**；
     不要自造人物名、势力名、章节标题。附录 B 是界面元素到真实数据结构的映射。
   - `docs/ui-redesign-2026-09-15.md` — 上一版已实现面板的功能清单，可当"功能不能丢"的清单。
   - `docs/prototypes/2026-09-15-writing-workbench/index.html` + `design-tokens.md` —
     上一版 OpenDesign 原型（第 3 版）。**信息架构、边界态、文案语气可以参考；视觉方向这次改用
     Claude Code 桌面版，不要沿用纸墨配色。**

## 1. 用户与目标

- **用户**：中文长篇网文作者。每天做的事：和 AI 讨论故事 → 让 AI 写下一章 → 审阅 AI 的提案 →
  接受或打回 → 读改已接受的正文 → 盯伏笔、人物状态和未收束债务。
- **产品定位**：作者是决策者，AI 是稿手。任何"故事事实"只有作者接受后才生效。
- **设计目标**：
  1. 作者全程看不到工程术语与裸 JSON（诊断与进阶面除外）；
  2. 打开就是**故事地图**：一眼看清人物、关系与进度；
  3. 从"看"到"写"到"审"到"读"每一步 ≤3 击；
  4. 像编辑部的工作台：安静、耐读、信息密度适中，适合每天长时间面对。

## 2. 产出要求

- **一个 HTML 文件**（内嵌 CSS/JS，可离线双击打开），顶部一条细长的「原型屏幕切换条」在全部屏幕间跳转；
  原型内部的真实交互（点节点、开抽屉、审提案、接受/回滚）必须能点通。

  无 lorem、无 TODO、无死按钮。
- 不引用任何外部资源（图片/CDN/字体/图标库）；图标用内联 SVG 或字符；只用系统字体栈。
- 另附 **design-tokens.md**（CSS 变量：日/夜两套颜色 + 字阶 + 间距 + 圆角 + 组件清单）

### 3.2 字体与字阶

| 角色 | 字体栈 | 规格 |
| --- | --- | --- |
| 界面控件 | `"PingFang SC","Microsoft YaHei",system-ui,sans-serif` | 13–14px，管理类信息密度 |

### 3.3 形状与密度

- 卡片圆角 8–10px，控件 6px，keycap/徽标 4px，药丸形只用于标签。
- 分隔优先用 1px 线，其次用底色差一档；不使用重投影与大色块。
- 留白充足，主画布两侧 24–32px 内边距，卡片内 16px。
- 日/夜双主题，默认跟随系统，写作台顶部可切换（夜间是**暖深灰**，不是纯黑）。

## 4. 信息架构（骨架必须严格遵守）

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏：项目名《雾港夜航：第七码头》 · 版本 R5 · 当前章 · [进阶] · [日/夜] │
├──────────────┬───────────────────────────────────────┬───────────────┤
│ 左栏（三段） │ 主画布（可切换，默认故事地图）         │ 右栏（常驻）   │
│ ① 作品       │                                       │ 当前章卡片     │
│   卷一 24 章 │  地图 / 正文 / 提案审阅 / 伏笔与线索 / │ 待审提案入口   │
│   第 6 章 ⏳ │  未收束债务 / 人物与关系 / 时间线 /    │ 最近 AI 活动   │
│ ② 线程       │  写作记忆 / 推演 / 版本历史 / 进阶面   │ 角色状态摘要   │
│   第 6 章·稿 │                                       │               │
│   全书·规划  │                                       │               │
│ ③ 视图       │                                       │               │
│   故事地图…  │                                       │               │
│ ──────────── │                                       │               │
│ [进阶]       │                                       │               │
├──────────────┴───────────────────────────────────────┴───────────────┤
│ 底部输入：自然语言指令 + `/` 命令 + `@` 引用 ｜ 继续写第 7 章 · 审阅本章 │
└──────────────────────────────────────────────────────────────────────┘
```

- **左栏①作品**：卷 / 章树，每章带状态徽标（已接受 / 待审 / 计划中 / 有未收束债务）。
  点击章节 = 主画布切到该章（正文或提案审阅，取决于它的状态）。
- **左栏②线程**：Session 列表，每条标注它服务哪一章或哪个阶段（如"第 6 章·冷库之下的通道"、
  "全书·路线规划"），活跃线程高亮；支持新建线程；**一个作品对应多条线程，共享同一套故事事实**。
- **左栏③视图**：故事地图、伏笔与线索、未收束债务、人物与关系、时间线、写作记忆、推演、版本历史。
- **底部「进阶」入口**：Cordis 插件树、插件清单、Agent preset、Jobs、Subagent、诊断原始数据。
  默认关闭，开启后左栏出现对应分组、主画布渲染这些面板（见 5.6）。
- **右栏**：当前章卡片（卷章号 / 标题 / 字数进度 / 状态）、待审提案入口（有提案时高亮 + 徽标）、
  **最近 AI 活动**（人话一句，如"第 6 章草稿已生成 · 6 条设定变更 · 3 个审阅问题"，不出现 JSON）、
  角色状态摘要（2–3 行）。
- **底部输入**：一条常驻输入区。左侧是线程选择（沿用②当前线程），中间是自然语言输入，
  `/` 触发命令候选、`@` 触发人名/章节引用；右侧是「继续写第 N 章」「审阅本章」两个动作和
  模型/权限指示。输入区不占主画布空间。

## 5. 交互与状态（逐条都要画出来）

### 5.1 提案审阅（核心屏）

- 顶部一行：`R5 → R6 · 卷二 第 6 章《冷库之下的通道》· 约 2,800 字 · 6 条设定变更 · 3 个审阅问题`。
- 正文预览区：可滚动阅读本章草稿（用附录 A 的正文片段，渐隐 + 「……」表示可继续）。
- **设定变更列表**：每条一句人话（如「陈默得知 3 号冷库存在地下通道」），右侧「接受 / 拒绝」
  二选一，默认接受，拒绝可留一句理由。**不出现 JSON / delta / kind 等词。**
- **审阅问题**：严重度标签（高/中/低）+ 问题 + 建议 + 出处锚点（显示成
  「第 4 章 · 陈默受伤」这样的可点引用，点击回到正文位置）。
- 底部：影响预览（`R5 → R6：正文 1 篇 · 设定变更 6 条 · 未采纳建议 2 条`，人话摘要）+
  主按钮「接受本章」+ 次按钮「暂不处理」。
- **必须画出「接受设定、拒绝正文」这条路径的结果态**：正文留在旧版本，设定变更按逐条选择写入，
  版本号变化，右栏活动行显示"已接受 5 条设定变更，正文未接受"。
- **过期提案态**：提案基于 R5、当前已是 R6 时，顶部显示「此提案已过期」+ 只能「丢弃」。

### 5.2 正文阅读

- 以正文阅读区为主（衬线、16–18px、行高 ≥1.8、行宽 ≤40 字），顶部显示章节标题与版本徽标。
- 段落可被锚点引用（审阅问题点进来时高亮对应段落）。
- 右上角提供「对比上一版」「回滚到此版本」入口。

### 5.3 版本历史

- 每个已接受版本一枚版本徽章（R1…R6）+ 一句人话摘要（如「R6：接受 5 条设定变更，第 6 章正文未变」）+
  对比 / 回滚。回滚要二次确认，确认后版本号与地图状态同步变化。

### 5.4 故事地图（默认首屏）

- 节点 = 人物，半径/描边反映戏份或本章出场，颜色反映势力（4 势力 + 无势力），节点上有状态点
  （情绪 / 未收束债务）。
- 边 = 人物关系，**同一条边表达双向语义**（上下两半或双线），hover 显示一句话摘要，选中节点时
  相关边加亮、其余淡出。
- 40–120 人的规模能力：按势力分簇、搜索定位、按卷/弧过滤「本卷出场」、拖拽钉位、缩放平移、图例；
  默认只呈现主要人物 + 主线关系，次要人物折叠成「+N」气泡。
- 参数：选定人物 → 右栏切到该人物摘要；双击 → 打开人物档案抽屉。

### 5.5 其他视图

- **伏笔与线索板**：每条含类型（伏笔/线索/谜团）、首次出现章节、当前状态、回收窗口、证据锚点。
- **未收束债务**：按"多久没推进"排序，临期项加提示色。
- **人物与关系**：人物档案（身份一句话、当前状态、情绪、弧线、关系列表、出场章节）。
- **时间线**：故事内时间（第 0 天 → 第 41 天）的事件流，与真实章节交叉引用。
- **写作记忆**：三条摘要 + 新鲜度（`基于 R5，最新`）+ 来源（第 5 章正文、关系投影、伏笔状态）。
- **推演**：实验列表（读者反应 / 人物压力）+ 「沙盒侧车未连接」说明卡 + 置灰的入口。
- **版本历史**：见 5.3。

### 5.6 进阶面（默认隐藏）

顶栏「进阶」开关打开后：左栏出现「内核 / Agent / 插件 / 任务 / 诊断」分组，主画布渲染对应面板，
**风格朴素但整洁、允许等宽**：Cordis 插件树（可挂载/卸载）、插件清单、
Agent preset 与模型/凭据、Jobs 列表、Subagent 列表、诊断（原始 JSON、事件日志、投影原始结构）。
关闭后整组消失，回到作者面。

### 5.7 边界态

1. **空项目**：地图区域是一张立项引导卡（三行说明 + 陶土按钮「让 AI 生成立项提案」）。
2. **加载中**：地图与侧栏骨架屏；按钮进入加载态（文案如「正在计算影响…」）。
3. **缺插件**：可读错误卡（如「未安装小说规划插件，本章合同暂不可用」+ 重试），页面其余部分正常。
4. **窄窗 1280**：左栏折叠为图标 + tooltip，右栏可收起，地图自适应，**不出现横向滚动**。
5. **AI 无输出 / 提案过期**：见 5.1 的过期态；AI 失败时右栏活动行显示可读原因 + 重试。
