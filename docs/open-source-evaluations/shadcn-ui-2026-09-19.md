# shadcn/ui for the workbench dialogs — evaluation and adoption (I-P4, 2026-09-19)

**Work order:** `tasks/frontend-polish-handoff-2026-09-19.md` §I-P4 (A10) — every modal
and popover in the novel-mode frame goes through one component library.

**Decision:** adopt the **Radix primitives** Radix Dialog and Radix Popover, and keep
the arrangement in this product's own token sheet. Do **not** vendor shadcn/ui's own
component source.

---

## 1. Why not shadcn/ui verbatim

shadcn/ui is not a package. It is component source you copy into your project, and
that source is **Tailwind utility classes over Radix primitives** plus `clsx` /
`tailwind-merge`. This repository has no Tailwind and is not going to grow one:

- `packages/novel-workbench/src/client/workbench-css.ts` is the product's single
  stylesheet, ported verbatim from the prototype by `scripts/port-prototype-css.mjs`,
  and every surface is drawn from its tokens (`--r-card`, `--sh-3`, `--fs-*`, `--s*`).
- A10 asks for one radius, one shadow and one animation curve across every dialog;
  A12 asks for those to come from a single token source. A second styling system
  would have to be translated back into that source, and the translation is where
  the two would drift.

What shadcn/ui actually buys — focus scope, Escape, outside-pointer dismissal, scroll
lock, `aria-hidden` on the page behind, anchored positioning — is the behaviour of the
Radix primitives underneath it. Taking those directly is the same adoption with the
translation layer removed.

**Assets:** no shadcn/ui code, theme, class names or demo markup is copied. The look is
written here.

## 3. Bundle cost (measured)

The workbench client bundle is bundled by tsdown, **CJS, unminified**, and is the only
artifact the DSH client module system loads. `react` / `react-dom` stay external (the
module system supplies them), so the two primitives ride inside it.

| | `lib/client.js` |
| --- | --- |
| before I-P4 | 1,685,186 B |
| after I-P4 | 1,898,415 B |
| delta | **+213,229 B (+12.7 %)** |
| guardrail | 2,400,000 B (79.1 % used, 501,585 B headroom) |

A standalone esbuild probe of the two primitives (same external set, unminified) measured
+170,537 B; the difference is tsdown's CJS wrapper plus the `@floating-ui` family that the
popover pulls in and the probe's entry did not exercise.

## 4. DSH seam

- **Portal, or not.** shadcn/ui portals to `document.body`. This frame does not:
  `shell.overlay` already renders above the three columns, and the frame's tokens hang
  off `[data-novel-workbench="frame"]` — a body portal would drop the night palette on
  the one surface the author is looking at. Radix behaves identically without a portal;
  `aria-hidden` is applied to whatever is outside the panel either way.
- **Focus return.** Radix restores focus to its own `Dialog.Trigger`. None of these
  surfaces has one — the sheet is opened from the topbar, the drawer from a cast card —
  so `NovelDialog` reads the opener during the render that turns `open` on and hands the
  keyboard back on close. Without that, Radix would leave focus on `<body>`.
- **Element naming.** Radix's prop types admit no `data-*`, so the surfaces' automation
  hooks (`data-novel-settings`, `data-novel-settings-close`, …) are spread through one
  typed cast at the primitive boundary. Every existing selector in the specs and in
  `scripts/smoke-workbench.mjs` still resolves.
- **API stability.** Both packages are stable-major, peer on `react@^16.8 || ^17 || ^18`,
  and are the substrate shadcn/ui itself tracks.

## 5. Accessibility: what actually changed

The hand-rolled trap this replaces took focus, cycled Tab and restored focus — and did
nothing else. `aria-modal="true"` was set on both surfaces as a promise that the rest of
the page was inert, and **nothing was making it true**: a screen reader went on reading
the rail and the transcript underneath the sheet.

Radix applies `aria-hidden` to everything outside the panel (`hideOthers`), locks the
page behind it (`react-remove-scroll`), refuses right-click dismissal, and wires
`aria-labelledby` from the dialog title. The I-P4 probe measures it: with the sheet open,
both the rail and the canvas sit inside an `aria-hidden="true"` subtree; on close, both
are clear again.

The hand-rolled `dialog-focus.ts` is deleted — it had no consumers left.

## 6. Verification

- **Unit** — `packages/novel-workbench/tests/novel-workbench-dialog-primitive.spec.ts`
  (one primitive for both arrangements; the page behind goes quiet and comes back;
  Escape; scrim; one radius/shadow/animation from one stylesheet) and the existing
  `novel-workbench-dialog.spec.ts` (focus in, Tab cycles both ways, focus restored)
  unchanged in intent. 504 tests pass.
- **Real machine** — `docs/evidence/2026-09-19/walkthrough/probe-i-p4-dialog.mjs` against
  an isolated Host on `127.0.0.1:4781`; screenshots `i-p4-settings-sheet.png`,
  `i-p4-person-drawer.png`, `i-p4-editor-menu.png` and `i-p4-dialog-summary.json`.
  Measured there: panel radius `10px` from the shared rule, `role="dialog"`,
  `data-state="open"`, background `aria-hidden`, Escape closes, the scrim closes, the
  menu's trigger reports `aria-expanded="true"` and an outside click closes it,
  0 console errors. The draft files in the probed workdir are byte-identical before and
  after.

## 7. Deliberately not changed

- **`AdvancedView`'s `<details>`** stays native. It is a disclosure of a raw Canon JSON
  dump, not a menu: it opens in place and stays in the flow. A popover is the wrong
  primitive for it, and a disclosure never needed dismissal.
- **`NovelLanding`'s planning card** keeps `role="dialog"` on an inline card that is part
  of the landing flow. It is not an overlay and does not behave like one; making it a
  modal would change the flow rather than the surface.
